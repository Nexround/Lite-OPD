# Hybrid SFT + OPD Training

[English](hybrid_sft_opd.md) | [中文](hybrid_sft_opd_zh.md)

## Overview

Hybrid SFT + OPD training splits each response into two supervised regions:

| Region | Source | Loss |
|---|---|---|
| **Gold prefix** | Provided by the dataset | Cross-entropy against gold tokens (SFT) |
| **Continuation** | Generated by the student at training time | KL divergence against the teacher (OPD) |

This lets you combine the stability of supervised learning (on a known-good prefix) with the exploration benefit of on-policy distillation (on the student's own generation). The two losses share a single backward pass — there is no extra forward step.

Set `gold_prefix_field: null` (the default) to disable hybrid mode and run standard OPD.

---

## Motivation

Standard OPD trains entirely on the student's own rollouts. This works well when the student can already produce plausible trajectories, but can be unstable early in training when the student has no prior anchor. Providing a gold prefix gives the student a correct starting point for each sample while still letting OPD shape the continuation.

Typical use cases:

- **Chain-of-thought anchoring** — supply the first few reasoning steps from a reference solution as the gold prefix; let OPD continue from there.
- **Format enforcement** — give a gold prefix that establishes the required output structure (e.g., `"<think>\n"`); the student learns to complete it on-policy.
- **Curriculum warm-up** — start training with long gold prefixes and shorten them over time (by reducing `gold_prefix_max_tokens`), gradually shifting supervision from SFT towards OPD.

## How It Works

### Token-level view

```
input_ids (one training sample):
┌───────────────────┬─────────────────┬──────────────────────────┐
│   base prompt     │  gold prefix    │      continuation        │
│  (user message    │  (from dataset) │  (student-generated      │
│   + chat header)  │                 │   during rollout)        │
└───────────────────┴─────────────────┴──────────────────────────┘
 ◄──────────────── prompt_len ────────►◄──── response_tokens ────►

Supervision:
                    ├─── SFT (CE) ───┤├──── OPD (KL) ───────────┤
```

- **Gold prefix** is embedded into the prompt via `continue_final_message=True` in `apply_chat_template`. From the rollout engine's perspective it is part of the context, not a generated token.
- **Continuation** is what the student generates during rollout. The teacher scores it with its own forward pass, enabling the KL loss.

### Training step

```
1. For each sample, read gold_prefix from dataset[gold_prefix_field].

2. Build the rollout prompt:
     apply_chat_template([user_msg, assistant(gold_prefix)],
                          continue_final_message=True)
   → The prompt string ends mid-assistant-turn.

3. Rollout: student generates continuation tokens from the end of
   the gold prefix.  Only continuation tokens are returned.

4. Pack sequences:
     input_ids = tokenise(rollout_prompt) + tokenise(continuation)
   PackedBatch records gold_prefix_lengths[i] ≈ len(tokenise(gold_prefix)).

5. Teacher forward (inference_mode):
     teacher_hidden = teacher.model(input_ids)

6. Student forward:
     student_hidden = student.model(input_ids)

7. Loss computation (per sample):
   a. SFT region  [sft_start : response_start]
        target_ids = input_ids[sft_start+1 : response_start+1]  ← gold tokens
        loss_sft   = CrossEntropy(lm_head(student_hidden[sft]), target_ids)
   b. OPD region  [response_start : response_end]
        loss_opd   = KL(teacher_probs ‖ student_probs)

8. Backward (two_stage mode):
   Stage 1 — accumulate ∂loss/∂hidden for both regions onto a single
             hidden_grad_accum tensor.
   Stage 2 — one backward call through the transformer backbone.
```

### Loss formula

For a single sample with `G` gold-prefix tokens and `C` continuation tokens:

```
total_tokens = G + C

loss = Σ_{t=0}^{G-1}   (G / total_tokens) × sft_loss_weight × CE(t)
     + Σ_{t=0}^{C  }   (chunk_len / total_tokens) × KL(t)
```

Both terms are further scaled by `response_tokens / total_response_tokens` across the batch (same normalisation as standard OPD).

Setting `sft_loss_weight = 1.0` gives equal per-token influence to SFT and OPD. Increasing it amplifies the SFT signal; decreasing it lets OPD dominate.

## Backward Pass Details

Hybrid mode works with all three `kl_backward_mode` values.

### `two_stage` (default, recommended)

The SFT and OPD regions share a single detached **leaf tensor** that covers both:

```
hidden_leaf = student_hidden[sft_start : response_end].detach().requires_grad_(True)
                              ├── [:G]  SFT chunk ──┤
                              ├── [G:]  OPD chunks ─┤  (8 sub-chunks)
```

Stage 1 — per-region gradient accumulation:
- SFT: `autograd.grad(loss_sft × scale_sft, [hidden_leaf, *lm_head_params])`
- OPD: `autograd.grad(loss_opd_chunk × scale_kl, [hidden_leaf, *lm_head_params])` × 8

Both contribute to `hidden_grad_accum` at their respective positions. LM-head gradients are accumulated immediately.

Stage 2 — single backbone backward:
```python
torch.autograd.backward(student_hidden_packed, grad_tensors=packed_grad_accum)
```

The backbone sees the combined gradient from both regions in one pass.

### `chunk`

SFT backward fires first with `retain_graph=True` (OPD follows), then OPD chunks proceed as in standard OPD. Memory usage is higher than `two_stage` because the full computation graph is retained.

### `sample`

SFT loss and KL loss are combined into a single scalar before calling `.backward()`. Simplest implementation; highest memory cost.

## Configuration

Three new fields in `TrainConfig` control hybrid mode:

| Field | Type | Default | Description |
|---|---|---|---|
| `gold_prefix_field` | `str \| null` | `null` | Dataset field containing the gold prefix text. `null` disables hybrid mode. |
| `gold_prefix_max_tokens` | `int \| null` | `null` | Hard cap on gold-prefix length (tokens). Prefixes are truncated at the token boundary before packing. `null` = no cap. |
| `sft_loss_weight` | `float` | `1.0` | Relative weight of the SFT (CE) loss vs. the OPD (KL) loss. Must be positive. |

### Example config

```yaml
# Standard OPD settings (unchanged)
loss: reverse_kl
student_model: /path/to/student
teacher_model: /path/to/teacher
train_dataset: /path/to/dataset
output_dir: results/hybrid_run
kl_backward_mode: two_stage

# Hybrid SFT + OPD
gold_prefix_field: gold_prefix      # field name in your dataset
gold_prefix_max_tokens: 512         # null = no cap
sft_loss_weight: 1.0                # 1.0 = equal per-token weight
```

See `configs/qwen3_5_2b_9b_hybrid.yaml` for a complete example.

## Dataset Format

Your dataset must include a field whose name matches `gold_prefix_field`. All other fields are unchanged from standard OPD.

```jsonl
{
  "question": "Solve: x² - 5x + 6 = 0",
  "gold_prefix": "Let me factor this expression.\n(x - 2)(x - 3) = 0\nSo",
  "answer": "x = 2 or x = 3"
}
```

- **`question`** (or `problem` / `prompt`) — the user prompt, as in standard OPD.
- **`gold_prefix`** — the text that anchors the response. The student generates from the end of this text.
- **`answer`** (or `solution` / `canonical_solution`) — used only for evaluation accuracy; not used in the training loss.

If a sample has an empty or missing gold prefix it is silently treated as a standard OPD sample (no SFT region).

### Constructing gold prefixes

Gold prefixes can be derived from any source:

```python
# Option A: first N tokens of the reference solution
gold_prefix = tokenizer.decode(
    tokenizer(reference_solution).input_ids[:256]
)

# Option B: first K sentences of a chain-of-thought annotation
import re
sentences = re.split(r'(?<=[.!?])\s+', chain_of_thought)
gold_prefix = " ".join(sentences[:3])

# Option C: a fixed structural header
gold_prefix = "<think>\n"
```

## Implementation Notes

### Tokenisation boundary approximation

The gold prefix is embedded into the chat-template prompt string, so its exact token count within `prompt_ids` may differ slightly from `len(tokenise(gold_prefix_text))` due to BPE merges at the junction. `pack_sequences` uses the standalone tokenisation as an approximation. The discrepancy is at most 1–2 tokens and does not affect training correctness meaningfully.

### Teacher forward over the gold region

The teacher runs a full forward pass over the packed sequence including the gold-prefix region, but its hidden states for the gold region are never used in the loss — only the OPD continuation slice is consumed. This is a minor computational overhead. A future optimisation could mask the teacher forward to start at the gold-prefix boundary.

### Backward compatibility

Setting `gold_prefix_field: null` (the default) sets `gold_len = 0` for every sample. All new code paths short-circuit and the behaviour is identical to standard OPD. No existing configs require modification.

## Hyperparameter Guidance

### `sft_loss_weight`

| Value | Effect |
|---|---|
| `1.0` | Equal per-token gradient magnitude from SFT and OPD. Recommended starting point. |
| `> 1.0` | SFT tokens contribute more; useful when gold prefixes are high-quality and the student needs a strong anchor. |
| `< 1.0` | OPD tokens dominate; useful when gold prefixes are noisy or the student is already stable. |

Note that the effective ratio also depends on the relative length of the gold prefix vs. the continuation. For a prefix of 256 tokens and a continuation of 512 tokens, `sft_loss_weight = 2.0` gives roughly equal total gradient contribution from both regions.

### `gold_prefix_max_tokens`

Truncating long prefixes keeps the OPD continuation meaningful:
- Too long a prefix → student generates very few tokens → OPD loss is noisy.
- Too short a prefix → SFT provides little anchor → behaviour approaches standard OPD.

A range of **128–512 tokens** works well for math reasoning tasks where the gold prefix contains initial reasoning steps.

### Curriculum strategy

Decrease `gold_prefix_max_tokens` over training to shift from SFT-heavy early training towards pure OPD at the end:

```
Steps   0–100:  gold_prefix_max_tokens: 512   (strong SFT anchor)
Steps 100–200:  gold_prefix_max_tokens: 256
Steps 200–400:  gold_prefix_max_tokens: 0     (pure OPD, set field to null)
```

This requires separate config files and manual restarts for each stage, or a custom scheduler that updates the config.

## Limitations

- **No pure SFT mode** — `teacher_model` is still required; the OPD branch always runs on the continuation. If the continuation is empty (all tokens are gold prefix), the OPD loss is near-zero but the teacher still performs a forward pass.
- **Approximate gold-prefix boundary** — due to BPE tokenisation, the SFT/OPD split may be off by 1–2 tokens at the junction.
- **Teacher overhead on gold region** — the teacher processes gold-prefix tokens even though their hidden states are unused. This is O(gold_len / total_len) extra compute per step.
